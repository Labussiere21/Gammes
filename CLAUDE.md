# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Running the Generators

All generators run from the repo root and require Python 3 + Jinja2:

```bash
pip install -r _generator/requirements.txt

python _generator/generate.py               # bass scales  → fr/gammes/ + en/scales/
python _generator/generate_guitar.py        # guitar scales → fr/gammes-guitare/ + en/scales-guitar/
python _generator/generate_chords_guitar.py # guitar chords → fr/accords-guitare/ + en/chords-guitar/
```

Each generator appends its URLs to `sitemap.xml` without touching sections owned by other generators (identified by URL prefix). Run them independently; do not chain.

## Architecture

### Two layers

**Interactive apps** (root `.html` files): self-contained single-file apps. Each file has all CSS, JS, and data inline. No build step, no external bundles — just open in a browser.

**Static SEO pages** (generated): `fr/{section}/{root-slug}/{id}/index.html` and `en/{section}/{root-slug-en}/{id}/index.html`. Generated by Python+Jinja2 from `_generator/`. These are landing pages linking back to the interactive app.

### Generator structure

All generators share data imported from `generate.py`:

| Symbol | Description |
|--------|-------------|
| `ROOTS` | 12 canonical notes (C, Db, D … B) with `pc`, `name`, `fr`, `slug`, `slug_en` |
| `ENHARMONIC_ROOTS` | 5 enharmonic aliases (C#, D#, Gb, G#, A#) with `canonical_slug` pointer |
| `SCALE_DEFS` | 72 scale definitions with `id`, `label`/`label_en`, `iv` (intervals), `ls` (letter steps), `fam`, `group` |
| Helper functions | `build_scale`, `build_triads`, `interval_str`, `fr_note`, `pretty`, `scale_slug` |

New generators (e.g., for arpeggios) follow the same pattern: define data, import shared helpers, loop ROOTS × items, write `index.html` via Jinja2, call `update_sitemap`.

### Sitemap update pattern

Each generator's `update_sitemap()` reads the existing sitemap, strips its own URLs (by prefix), appends the freshly generated list, rewrites the file. This is idempotent and non-destructive for other sections.

### Interactive apps — key conventions

- **Instrument toggle**: `<div class="inst-bar">` with `.bass-btn` / `.guit-btn` links. Bass pages use `--brass:#d9a849` (gold); guitar pages use `--brass:#bf1828` (red).
- **Nav active state**: bass `color:#160f08` on gold; guitar `color:#fff` on red.
- **Notation/lang persistence**: `localStorage` keys `sbnot` (`'en'`=ABC / `'fr'`=solfège) and `sblang` (`'fr'`/`'en'`).
- **`style.css`**: shared base styles (eyebrow, nav-link at 11px/5px padding, inst-bar). Individual pages may load it via `<link>` or inline all CSS — be consistent with the file you edit.
- **Guitar instrument context on shared pages**: `cadences.html` is shared (no guitar equivalent). It uses `sessionStorage` key `sbinst` to detect guitar referrers and re-route the Tonalités nav link to `tonalites-guitare.html`.

### Arpège data (from `arpeges-basse.html` `GROUPS`)

Arpeggios are grouped by third type. Each entry: `{id, label, label_en, sub, iv[], sym, posType}`. Groups: Tierce Majeure (maj/dom/extensions), Tierce mineure (min/extensions), Sans tierce (sus/power), Quinte augmentée, Quinte diminuée.
